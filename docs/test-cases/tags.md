# Test Design & Checklist: Tags Module

Спецификация: `tags.yml`  
Эндпоинты: `/api/tags`

---

## 1. Smoke Tests (Позитивные критические пути)

| ID | Сценарий | Предусловия | Шаги / Тестовые данные | Ожидаемый результат | Приоритет |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **TC-TAG-SMK-01** | Получение списка тегов гостем (анонимно) | В базе существуют теги | `GET /api/tags` (без авторизации) | `200 OK`. Возвращает объект с массивом строк `tags: ["react", "nodejs", "qa"]`. | **Critical** |
| **TC-TAG-SMK-02** | Получение списка тегов авторизованным пользователем | Пользователь авторизован | `GET /api/tags`<br>Header: `Authorization: Token <jwt>` | `200 OK`. Возвращает актуальный список тегов. | **Major** |

---

## 2. Contract & Edge Cases (Контракт и крайние случаи)

| ID | Сценарий проверки | Воздействие / Запрос | Ожидаемый результат для клиента |
| :--- | :--- | :--- | :--- |
| **TC-TAG-EDG-01** | **Структура ответа tags: [string]** | Валидация JSON-схемы ответа `GET /api/tags` | Ответ строго соответствует схеме: корневой объект содержит ключ `tags` типа `array` с элементами типа `string`. |
| **TC-TAG-EDG-02** | **Поведение при пустой базе тегов** | Запрос `GET /api/tags` в пустой БД | Сервер возвращает `200 OK` с пустым массивом `{ "tags": [] }`; клиент отображает пустой state. |
| **TC-TAG-EDG-03** | **Появление нового тега после создания статьи** | Создание статьи через `POST /api/articles` с уникальным тегом `["blockchain"]`, затем `GET /api/tags` | Новый тег `blockchain` автоматически добавляется в глобальный список тегов. |
| **TC-TAG-EDG-04** | **Устойчивость к дубликатам тегов** | Создание нескольких статей с одинаковыми тегами | Глобальный список `GET /api/tags` содержит только уникальные теги без дублирования. |
